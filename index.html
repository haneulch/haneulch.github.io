원스토어 주식회사

앱 업데이트 트래픽 폭주 대응 및 확률적 자료구조 기반 DB 부하 최적화

📅 2025.05

새벽 특정 시간대에 일시적으로 집중되는 단말의 앱 업데이트 조회 API Call로 인해 발생하는 DB 과부하 문제를
장비 추가나 하드웨어 스케일업 없이 소프트웨어 구조 및 데이터 필터링 계층 고도화만으로 해결한 프로젝트입니다.

Situation & Problem
  • 매일 새벽 시간대 업데이트 조회 트래픽이 평상시 대비 10배 이상 폭주하며 DB CPU 점유율이 80%를 초과하는 위협 발생
  • 검출된 패킷 분석 결과, 전체 트래픽의 상당수가 실제 업데이트가 존재하지 않는 패키지의 중복성 쿼리임에도 매번 DB Disk I/O를 직접 조회하여 불필요한 부하 유발
Action & Result
  • 다계층 런타임 필터링 설계:
    요청을 DB에 조회하기전 1차 블랙리스트 제외,
    2차로 메모리 효율성이 극대화된 Bloom Filter를 거쳐 DB에 실존하지 않는 원본 데이터를 확률적으로 제외,
    3차로 Local Cache를 조합 적용
  • Result: 유효하지 않은 요청을 DB 관문 앞에서 90% 이상 블로킹하는 데 성공. 인프라 증설 비용 없이 DB CPU 사용률을 80%에서 30% 이하로 감소
보일러플레이트 60% 제거
원스토어 주식회사

Spring Cloud Stream 기반 메시징 아키텍처 추상화

📅 2024.12 - 2025.01 (2개월)

RabbitMQ와 Azure Service Bus가 공존하는 멀티 브로커 환경에서
Spring Cloud Stream 기반의 메시징 추상화를 통해 비즈니스 코드와 인프라 환경의 결합도를 낮춘 프로젝트입니다.

Situation & Problem
  • 인프라 종류에 의존적인 코드 분기로 인해 비즈니스 로직과 데이터 바인더 인터페이스간 결합으로 인한 중복 코드 발생 및 관리에 어려움 발생
  • 브로커 기술 변경(예: Kafka 도입 등) 시 소스 코드 전면 수정이 요구되어 확장 시의 기술적 유연성이 저해되고 신규 추가 시 높은 학습 장벽 존재
Action & Result
  • Binder 추상화 및 공통 로직 라이브러리화: Spring Cloud Stream의 선언적 바인딩(yaml 구성) 구조로 전면 개편. 브로커 종속성을 제거하고, 각 메세지별 순수 비즈니스 로직만 구현 유지할 수 있는 구조 확립
  • Result: 메시징 부속 코드가 약 60% 감소하여 순수 도메인 집중도를 향상시켰고, 새로운 구독 처리 로직 작성 시 소요 공수를 50% 이상 단축함
네트워크 오버헤드 70% 차단
(주)스테이지파이브

AWS SQS 기반 큐 아키텍처 재설계 및 미들웨어 메시지 최적화

📅 2023.02

대량 프로모션 유입 시 시스템 지연으로 인한 SQS 적체현상과 주문 시스템이 지연되는 연쇄 장애 위험을 해결한 프로젝트입니다.

Situation & Problem
  • 기존 구조는 큐에 들어온 단순 키(ID)를 기준으로 메인 비즈니스 로직 동기화를 수행할 때마다 주문 시스템 API를 지속 재호출하는 구조
  • 프로모션으로 배송 추적 요청이 비동기적으로 급증하면서 큐 메세지 적체 현상 발생 동시에 주문시스템에 과도한 조회 요청으로 인해 주문 시스템에 지연을 유발하는 현상 발생
Action & Result
  • 메시지 페이로드 경량 설계 및 상태별 멀티 큐 배포: 주문 시스템 조회를 최소화하도록 필수 배송추적 메타데이터를 메시지 바디에 담는 구조로 변경. 배송 상태별(접수/배송/완료)로 전용 SQS 파이프를 다각화하여 특정 장애 영향이 고착되지 않게 분리
  • Result: 피크 타임 SQS 적체 현상 완전 제거, 주문 서비스 지연 현상 완전 제거
